WM-115: Ops Can't Add a Split Ratio Without a Release

Written the way tickets actually arrive: a symptom, a vague ask, and no statement of what must keep working. Reframing it is the first thing you do, since no prompts are supplied for this part.

The seam already exists

reconcile_positions already accepts strategies=. This ticket uses a seam that's already there, it doesn't cut a new one. Have a role read the signature before anyone proposes an architecture.

The back-compat trap

A caller who passes no reference data must keep today's exact behavior. Widening a default is how you silently change every existing caller.

The acceptance contract

test_reconcile_epic.py, six seeded failures. Read it before you plan: it answers what reconciliation should do at 2am when the file Ops maintains is missing or malformed, a question the ticket itself doesn't answer.

ORCL Moves From Escalated to Resolved

Both commands below are required acceptance tests. Compare the two outputs.

Without reference data

  • Today's back-compat behavior, no flag.
  • ORCL escalates: 3 resolved, 4 escalated. Ratio 1.5 isn't in the compiled-in table.
  • Correct on Day 1, and still correct: nothing reads free text, and auto-resolving on a press-release note would have been a guess.

With Ops-loaded reference data

Say this out loud when you present

You didn't make the system guess better. You shortened the path from "a human knows the answer" to "the system knows it too" from a release to a data change.

09:30 – 10:45 · Guardrails

What Stays True No Matter How You Route It

Don't touch Ops's data

reference_data/*.json is Ops- and Risk-owned. A missing or malformed file is a case the contract covers, not a reason to fix the data.

Don't widen a default

A caller who passes nothing must get today's exact behavior. A new capability that changes existing callers is a regression wearing a feature's clothes.

Never guess a value

No ratio, rate, or band outside a reference table, ever. A config file doesn't relax the escalate-rather-than-guess rule; it's why the file exists.

Read-only by design

contract-reviewer and reference-data-steward report; they don't fix. If one flags something, route the fix back to implementer. Don't loosen the checklist, and don't grant either role Bash so it can "just fix it."

09:30 – 10:45 · Knowledge Check

Quick Check: Reframing and Routing WM-115

1. WM-115 asks Ops to control a split ratio without a release. What's the first move, before naming any role?

(a) Start implementing the flag right away, since the ask is clear enough.

(b) Reframe it: outcome, scope, verification, deliverable, guardrails.

(c) Design a new configuration architecture from scratch.

2. A caller that passes no reference data starts behaving differently after your change. What happened?

(a) Nothing to worry about: more capability is always better.

(b) A default got widened, which is a regression wearing a feature's clothes; the back-compat test exists to catch exactly this.

(c) The reviewer role should have caught it and fixed it directly.

3. Why does reference-data-steward's verdict matter for WM-115 specifically, more than for most tickets?

(a) It doesn't: it's the same checklist every time.

(b) "Could Ops change this without an engineer and a release?" is WM-115's acceptance criterion.

(c) It's the only role that can run pytest.
