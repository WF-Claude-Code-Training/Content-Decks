13:30 – 14:45 · The Spine

Three Layers of Control

Labs 4 and 5 built roles. This lab is where the roles become a framework, because it holds all three kinds of control at once.

Layer What it is How it fails
Skill A procedure, written down once, that travels with the repo Silently, if nobody invokes it
Subagent An independent opinion, in its own context, with its own tool budget Arguably, a reviewer can be wrong or talked around
Hook A deterministic denial before a tool call runs Loudly, or not at all, it cannot be reasoned with
The important part isn't how to write a hook. It's learning which guardrails deserve one.
13:30 – 14:45 · The Decision Test

Choosing the Layer Is the Design Work

Lab 4's check_pod.py labelled two roles "contract-only": asked, not prevented, from crossing the test/source line. A tools: list gates tool types, not file paths. Layer three is the answer to that gap.

The test

  • Could a well-intentioned, competent engineer violate this by accident?
  • Could review miss it?
  • Are the consequences something you can't take back?

If yes to all three, it's a hook.

The cost of getting it wrong

  • Under-enforce: you're relying on diligence alone
  • Over-enforce: a judgment call gets hooked, and people route around it
13:30 – 14:45 · Why a Hook Is Different

A Hook Is the Only Guardrail That Isn't a Request

A PreToolUse denial happens before the tool runs. It doesn't negotiate.

  • A Skill can be skipped. Nobody enforces that it gets invoked.
  • A subagent can be wrong, shallow, or talked around by a persistent ask.
  • A hook can't be reasoned with. That's the point, and why it's reserved for mistakes you can't take back.
  • Hooking everything is its own mistake: a hook that blocks a legitimate change gets disabled on day one.
13:30 – 14:45 · Once You've Decided It's a Hook

Two Shapes of Hook

This decides how much work you're in for.

Additive check Subtractive check
Asks Does this add something forbidden? Does this remove something required?
Needs Only the text being introduced The simulated result vs. what's on disk
Example no_print.py (shipped, read it) protected_regions.py (yours to write)
Most real guardrails are subtractive. Reading the tool input alone can't answer them.
13:30 – 14:45 · The Mechanics

The Hook Interface

One interface, reusable for any PreToolUse hook. This is what makes a hook a control instead of a suggestion.

In

  • The PreToolUse event arrives as JSON on stdin
  • Tool name, tool input, file path all included

Out

  • Exit 0 allows the tool call
  • Exit 2 blocks it, reason on stderr

What stderr really is

  • Claude Code feeds it back to the model
  • It's a prompt, not a log line
  • Name the legitimate alternative, don't just refuse
13:30 – 14:45 · Two Decisions the Tests Don't Make for You

Fail Open or Fail Closed?

Same question, possibly a different answer, every time you write a hook.

no_print.py fails open

  • Every "can't tell" path returns 0
  • The docstring says why: it's one layer among several, a miss gets caught downstream

Yours may need to fail closed

  • It protects a fee table review already missed once
  • A regex check will block a semantically identical reformat, and that's a written-down trade, not a discovered bug
A hook with a known, documented blind spot is stronger than one with an assumed-perfect reputation.
13:30 – 14:45 · Worked Example, Then Yours

Read One, Write One

no_print.py ships done: it blocks a print() added during the logging rollout. Read it before writing protected_regions.py, the harder, subtractive shape.

.claude/hooks/protected_regions.py, the check at its heart

violations = [
    entry for entry in entries
    if entry["snippet"] in current and entry["snippet"] not in new_content
]
if violations:
    print("Blocked: this edit would remove or alter a protected region:",
          file=sys.stderr)
    sys.exit(2)  # exit 2 = PreToolUse denies the tool call
  • Handles Write, Edit, and MultiEdit
  • Allows a logger.info(...) call inserted next to a protected region
  • Blocks only when a protected snippet would actually disappear

13:30 – 14:45 · Closing Lab 4's Gap

Managing Guardrails in a Pod

Where a hook lives, and how strictly, is a pod-level decision, not just a scripting one.

Session-scoped

  • Wired in .claude/settings.json
  • Applies to every tool call, every role
  • What both this lab's hooks use

Agent-scoped

  • Attached to one subagent's own frontmatter
  • Turns "never edit a test file" from contract-only into tool-enforced, for that role alone
  • This is how Lab 4's gap closes for real
Contract-only vs. tool-enforced is the difference between a framework and a wish.
13:30 – 14:45 · The Collision

Two Reviewers Earn Their Keep by Disagreeing

logging-reviewer checks conformance. risk-officer checks audit sufficiency. They should disagree.

logging-reviewer

  • Event names, field conventions
  • Routine paths staying silent
  • Nothing else in the diff changed

risk-officer

  • Could an analyst reconstruct the decision, not just the outcome?
  • Read-only by design: Read, Grep only
Don't resolve a disagreement by picking a favorite or loosening a checklist. Decide, and record the outcome: extend the convention, or accept the gap in writing.
13:30 – 14:45 · Optional Stretch

A Third Way to Review: Workflows

Skip-safe, and worth a look if your environment has it. A workflow trades a subagent's judgment for a script's coverage.

What it is

  • .claude/workflows/audit-review.js fans out across four dimensions at once
  • Each finding then goes to two independent skeptics told to refute it
  • Control flow lives in code, not in a model's judgment

When to reach for one

  • It's the pairing review you'd give yourself with unlimited patience: reread the same diff once per concern, then argue with your own findings
  • Worth it once that discipline needs to happen every time, not just when you remember to
  • Wrong tool for a single bounded task; you're paying for coverage, not speed

Compare it to what you built

  • Run it against your own WM-109 diff
  • Which findings did it surface that your two reviewers didn't?
  • Were they worth the cost? Be willing to conclude no
A workflow buys coverage and confidence, not speed. Use it when you'd otherwise have to choose between being thorough and being finished.
13:30 – 14:45 · The Discipline

What Not to Hook

A framework is defined as much by what it declines to enforce as by what it blocks.

  • Never log raw PII: important, but what exactly matches? A hook that fires on every string field is a nuisance, not a control.
  • Don't widen scope beyond three named modules: trivially hookable by path, until a legitimate fourth module needs logging.
  • "We considered a hook here and chose not to" is a stronger position in a design review than never having thought about it.

13:30 – 14:45 · Knowledge Check

Quick Check: Build the Enforcement Layer

1. A guardrail says "don't alter the fee-tier table during a logging rollout." Which layer?

(a) Skill

(b) Subagent

(c) Hook: one careless edit misprices every fee, review already missed it once, and there's no legitimate exception

2. What makes a hook "subtractive," and why is it harder than an additive one?

(a) It only scans the text being added

(b) It asks whether a change removes something required, so it must simulate the file after the edit and compare it to disk

(c) It runs after the tool call instead of before

3. A PreToolUse hook exits 2 and writes to stderr. What happens to that message?

(a) It's written to a log file and nothing else

(b) Claude Code feeds it back to the model as a prompt, so the denial should name the legitimate alternative, not just refuse

(c) It's discarded once the tool call is blocked

4. Why can't a tools: list express "this role may edit source but never tests"?

(a) Subagents can't be given Edit at all

(b) A tools list gates tool types, not file paths; an agent-scoped PreToolUse hook is the missing expression

(c) It can, with the right YAML syntax

5. logging-reviewer approves; risk-officer flags a missing field. How do you resolve it?

(a) Go with whichever reviewer approved

(b) Loosen the checklist until both agree

(c) Decide and record it: extend the convention, or accept the gap in writing
